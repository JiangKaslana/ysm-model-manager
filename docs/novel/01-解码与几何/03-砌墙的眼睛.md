# 第 01 区域 · 第 3 章 · 砌墙的眼睛

> 区域归属：`01-解码与几何`（`frontend/src/views/app-preview/index.ts` `frontend/src/utils/3d/adapters/mount-preview-core.ts` `vrm-bone-ui.ts` `mmd-controls.ts`）
> 时间线标签：vol-4
> 对应真实事件/代码改动：app-preview 等四个视图入口的 `import.meta.hot.accept(cb)` 自接受边界吞掉整棵依赖子树的 HMR 更新，改为 `accept("./css.ts", cb)` 只热刷样式表（2026-08-16 实测，vite 日志 `hmr update /src/views/app-preview/index.ts (x15)`）

---

## 一 · 第十五次敲门

外科医生第十五次保存。

屏幕上的 3D 菜单纹丝不动。新加的「🦴 骨骼」按钮没出现，改过的面板样式没生效，连那个应该新长出来的骨骼面板，都像是从没被写进过任何一行代码。

外科医生把终端翻过来，指着一行字：

```
14:02:55 [vite] hmr update /src/views/app-preview/index.ts (x15)
```

十五次更新，十五次都报在同一个文件上。那些真正被改动的地方——`mount-preview-core.ts`、`vrm-bone-ui.ts`、`mmd-controls.ts`——一个名字都没露脸。

「我加的按钮呢？」外科医生问。

眼（`app-preview`）很委屈：「我什么都没收到。」

它说的是实话。从它这一侧看过去，一切风平浪静。没有更新敲门，没有新东西递进来，连一丝风的动静都没有。

但 bus.js（心）不信。心最清楚血脉的流向——外科医生改了文件，vite 重新编译了，心跳跳了十五下。**更新一定离开了源头。那它在哪条血管里消失了？**

---

## 二 · 一堵只有一个窥视孔的墙

bus.js 顺着依赖的血管往回摸，一直摸到 `index.ts` 的末尾。那里砌着一堵墙。

```ts
import.meta.hot?.accept((newModule) => {
  const style = (newModule as any).appPreviewStyle;
  document.querySelectorAll("app-preview").forEach((el: any) => {
    const root = el.shadowRoot;
    if (root) root.adoptedStyleSheets = [style];
  });
});
```

「这堵墙是我自己砌的。」眼小声说，「为了光影变了的时候能立刻换脸，不用整座塔重来。」

光影，就是样式。眼爱美，它不想为了换个颜色、调个间距，就惊动全身重来一遍。所以它砌了这堵「热更新墙」，又在墙上留了一个窥视孔——`appPreviewStyle`，那张挂在 Shadow DOM 里的样式表。

但问题恰恰在这里。

**新按钮比窥视孔大。新面板比窥视孔大。连 3D 菜单的样式，都比窥视孔大。**

bus.js 盯着那几行代码，终于看清了十五次心跳的下场：每一次，更新沿着血管涌到 `index.ts` 这堵墙前。墙说「我接收了」——`accept` 就是这个意思——然后把更新交给那个回调。回调只做一件事：重挂那张样式表。它不重渲染，不重挂载，连看都不看新按钮一眼。

更让它心凉的是第三件事。3D 菜单的样式住在 `ui-components-styles.ts` 里，是**光天化日下的 light DOM**，根本不住在眼的 Shadow DOM 里。可眼的窥视孔只朝自己的影子看。于是连「样式」这种本该最轻的更新，也一起被吞了。

**接收了，然后丢弃了。合法，静默，看不见。**

---

## 三 · 自接受，就是自盲

「所以这堵墙不该存在？」眼问。

「不。」bus.js 说，「问题是——你把自己声明成了**整条血脉的边界**。」

它拆开 `accept(cb)` 这两个字。无参的 `accept` 是「自接受」：模块宣布，所有流经我的更新，都由我消化。于是眼成了它整棵依赖子树的唯一边界——`mount-preview-core` 的改动冒泡到它，`vrm-bone-ui` 的改动冒泡到它，`mmd-controls` 的改动也冒泡到它。

而它的消化器官，只有一个窥视孔。

bus.js 顺藤摸下去，心更沉了。`app-content`、`app-sidebar`、`app-tree` 三处入口，砌着**同一堵墙**。四个器官，四条血脉，全在入口给自己开了同一个只放得下「光影」的窥视孔。

修法不是拆墙——墙必须存在，局部换脸是必要的。修法是**把窥视孔改成只认那一个具体的名字**：

```ts
import.meta.hot?.accept("./css.ts", (newCssMod) => {
  const style = new CSSStyleSheet();
  style.replaceSync((newCssMod as any).previewCSS);
  document.querySelectorAll("app-preview").forEach((el: any) => {
    if (el.shadowRoot) el.shadowRoot.adoptedStyleSheets = [style];
  });
});
```

`accept("./css.ts", cb)`——墙只认「光影」这一个入口。样式变了，照旧局部换脸；**别的更新，不再被这堵墙吞下，而是落下去，让整座塔重新醒一次。**

眼眨了眨，明白了：「所以不是我瞎，是我把自己砌成了一座只开一扇小窗的房子，还在门上挂了块『我都能处理』的牌子。」

---

## 尾声

眼后来总想起外科医生第十五次保存的样子。

那不是一次失败的修改。那是十五次**被无声吞掉的敲门**。墙每次都彬彬有礼地回答「已接收」，然后转过身，什么都没做。没有报错，没有警告，甚至没有一句「我不认识这东西」。

**缝**：`import.meta.hot.accept()` 的「自接受」是一堵墙——它本为局部热更新而砌，却把整个依赖子树的更新都揽成了「已接收」，而它的处理器只认识样式表这一种东西。墙在保护热更新，同时也在隔离更新本身。边界越「自动」，被它吞掉的东西越没有尸骨。

---

**教训**：自接受即自盲，边界把更新也隔离了。
